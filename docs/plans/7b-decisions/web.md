## For Innocent

### WEB-1 · Which files may load before the demo login

**The story.** The login screen (SCR-12) is part of the React app in `apps/web`. To draw it, the browser has to download
the app's built script and style files (hashed names such as `/assets/index-3f9a.js`) and its fonts. You decided (R-48)
that one login gates the whole deployment, and the acceptance line says "every route except the login and `/healthz`
refuses an unsigned request"; SCREEN_SPECS SCR-12 says the same ("the only route, with `/healthz`, that answers without
a session"). Read literally, `/login` would answer but its own files would be refused, so the reviewer would see a blank
page and could never sign in. Those files hold no data: every customer, case, number and reset sits behind `/api`, which
stays gated whatever you pick, and the same code is in the public repo (R-42). The choice only changes what an unsigned
stranger can download, and how far the build departs from R-48's wording. It is cheap to change later (one registry list
in `web/frontend.py`), except option B, which adds a second screen to maintain.

**Option A: `/login` plus the built files under `/assets/` and `/fonts/` are public; every other page and every `/api`
call needs the login (recommended).** No extra work. R-48's line gains "plus the login page's static files". AEA-49
gets the `risk::security` label (it now decides what an unsigned visitor can fetch, WEB-36).
**Option B: a separate, self-contained login page (styles and script inlined) at `/login`, nothing else public.** Keeps
R-48's letter exactly. About half a day, and a second login screen that must keep matching SCR-12's design and copy.
**Option C: the whole app shell is public (any page path returns the app), and only `/api` is gated; the app sends
itself to `/login` after a 401.** Simplest server. An unsigned visitor briefly sees the empty frame of the staff screens
before the redirect, and the server-side redirect of WEB-28 moves into the browser. Departs furthest from SCR-12.
*Recommended: A,* because the login works with no extra build, nothing with data becomes public, and the deviation from
R-48 is limited to files that are already public in the repo.

**Decision needed:** Which files may load without the demo login: `/login` plus its built asset files (A), a separate
self-contained login page only (B), or the whole app shell (C)?
