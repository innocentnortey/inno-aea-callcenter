## [AEA-51] integration A: the customer path end to end

_Conventions for every inno-aea-callcenter issue (from the approved breakdown, `docs/plans/slice-plan.md`):_
repository `/home/linuxuser/workspaces/inno-aea-callcenter` (package `src/meridian/`, tests `tests/`, eval `eval/`); GitLab
`innocentnortey/inno-aea-callcenter`. Read first: `CLAUDE.md`, `.claude/README.md`, `.claude/reference/area-map.md`, the
slice plan's row for this issue, `docs/design/code-design.md` (DO-3) and `docs/design/contracts/internal-components.md`
(DO-4: exact types and signatures). Vocabulary: PRD R-n, US-n, WP-n, HP-n, WF-n, CAP-n, E-n, M-n, CON-n as their owner
documents define them. Workflow: `lane::build-loop` issues run plan (`fanout-planner`, plan meets
`to-tickets/templates/implementation-plan.md`) → implement (`fanout-implementer`) → test → `code-review-agent`; affected tests
only (`.claude/rules/build-loop-test-scope.md`); `risk::security` issues get frozen failing tests first and the security
agent at their wave merge. **Siblings in the same or a later wave are called through their DO-4 signature by injection
(constructor, `GraphDeps`, or `web/deps.py`) and tested with a double; a plan that needs more than that signature records
`blocked-on AEA-NN` instead of inventing behaviour.** Never: edit the briefing, issued data or `docs/archive/`; edit
`docs/ux/03-structure/ui-contracts.openapi.yaml` or `UI_CONTRACTS.md` (a needed change stops the issue and goes to
Innocent); touch `apps/web/**` or `docs/ux/**`; edit another issue's owned file (collision map, slice plan §3); put a
secret, verification code, card-like number or full phone number in code, logs, traces, fixtures or test names; call a
paid model in a default test (mark `live`); bind ports 4019 or 5184; `git add -A`. Evidence: every criterion names its
test or command and the result a reviewer should see; numbers come from runs, never from targets.

**The integration harness every criterion uses** (the "real entry point"; slice plan Amendment 1: "AEA-51 / 52 run on the
harness (AEA-57), not on fakes at the TestClient"): AEA-57's `tests/journeys/support/` builds the real app from
`web/container.py` on a disposable copy of the issued DB (`temp_sqlite`), runs it in a thread on an ephemeral port, signs
in with its login helper (CON-22), and reads stored rows with its DB-state reader. The real `DemoClock` starts at
`DEMO_START`, Fri 2026-10-16 10:00 America/Chicago (cases.md §6; R-3), and the real `FastembedIndex` reads an index built
once per test session by the ingest CLI from the 17-file manifest. **Only two things are substituted, both through `ContainerOverrides`
(web.md §15, R-W-8):** AEA-57's deterministic scripted model adapter at the provider boundary (it returns the raw planner, classifier, specialist,
responder and brief output each test script fixes, so the production parsers and schemas run; a deployed configuration
cannot select it; never a paid call), and the trace exporter (in memory, behind AEA-19's real mask hook, as DO-6 *Capture
verification* requires). Worked-pair customer data comes from the issued DB or from each pair's stated assumption in
`docs/data/worked-pairs.md`; phone numbers and codes are read at run time from the working copy and the demo inbox, never
written into a test file. Every response is checked with `tests/api/openapi_check.py::assert_response_matches` (web.md
§13).

**Scripted outputs are adversarial on purpose.** Where a hard gate is code's job, the script tries to break it (moves a
fee-bearing visit, claims "Done", invents a number, reads an invoice before the code) and the test proves code stops it.
Free-text quality is not judged here; that is Stage 9's E-1 run with real models.
